# Nhật Ký Công Việc - Dự án WorkTracker
**Ngày chốt:** 20/07/2026
**Thực hiện bởi:** Đội ngũ phát triển Backend

**Mục đích:** Tổng kết tiến độ, liệt kê các tính năng đã hoàn thiện ở phía Backend đối chiếu theo Tài liệu Thiết kế Hệ thống (System Design Document - Chap 1, 2, 6). Tính từ lúc khởi tạo dự án đến thời điểm hiện tại.

---

## 1. Môi trường và Cấu trúc Hệ thống (Infrastructure)
- **Framework Lõi:** Khởi tạo thành công kiến trúc Django và Django REST Framework (DRF).
- **Cơ sở dữ liệu:** Cấu hình và kết nối thành công với PostgreSQL (`worktracker_db`).
- **Cache & Tối ưu:** Tích hợp hệ thống Redis (`django-redis`) để tối ưu hiệu năng.
- **Bảo mật kết nối:** Cấu hình thư viện `corsheaders` chuẩn bị giao tiếp đa miền với Frontend React.
- **Tài liệu API (API Contract):** Tích hợp thành công `drf-spectacular` tạo trang giao diện Web Swagger (`/api/docs/`), tự động quét và vẽ tài liệu cho toàn bộ Backend.

## 2. Hệ thống Xác thực và Phân quyền (Auth & RBAC) - [Chương 1 & 2]
- **Authentication (NFR-01):** Triển khai cơ chế cấp phát cặp khóa Access Token / Refresh Token bằng chuẩn bảo mật JWT (`rest_framework_simplejwt`).
- **Tối ưu Khóa Tài khoản (NFR-04):** Viết class Authentication tùy chỉnh (`CachedIsActiveJWTAuthentication`) để kiểm tra trạng thái hoạt động của tài khoản qua Redis trên mọi Request, đảm bảo tính năng khóa tài khoản có hiệu lực ngay lập tức (Immediate Lock) mà không gây nghẽn Database.
- **Phân quyền Đa lớp (RBAC):** Xây dựng thành công hàng rào bảo mật 3 lớp chặt chẽ:
  1. `IsActiveAuthenticated`: Xác nhận người dùng hợp lệ.
  2. `IsManagerRole`: Xác nhận chức danh (Admin, Manager, Employee).
  3. `HasPermissionCode`: Kiểm tra quyền hành động cụ thể ở cấp độ chi tiết (Action-level, VD: `job:create`, `report:export`).
- **Seeding Data:** Hoàn thiện script `seed_manager_permissions.py` để tự động nạp danh sách 22 quyền cơ bản cho chức danh Manager.

## 3. Module Quản lý Dự án (Projects & Jobs)
- Áp dụng cấu trúc Database chuẩn hóa (Tách biệt logic tài khoản và hồ sơ nhân viên).
- Hoàn thiện bộ API cho chức năng quản lý Job (tạo, sửa, đổi trạng thái).
- **Scope-level Security:** Xây dựng các hàm lọc `scoped_jobs`, đảm bảo Manager chỉ được phép nhìn thấy và thao tác với các Dự án do chính họ quản lý (`jobs.manager_id`).

## 4. Module Quản lý Công việc (Tasks & Kanban)
- Kết nối mô hình dữ liệu Tasks - Jobs - Users.
- Hoàn thiện bộ API hỗ trợ phương pháp luận quản lý Agile/Kanban:
  - Cung cấp dữ liệu dạng bảng kéo - thả (Kanban View).
  - API tạo task, phân công (assignee), thiết lập ưu tiên (priority) và hạn chót (deadline).
  - Quản lý luồng trạng thái của Task.
- **Tính năng Người theo dõi (Task Followers):** Hỗ trợ gán thêm nhiều người theo dõi một task để nhận thông báo.

## 5. Module Nhật ký Công việc (Timesheets & Time Lock)
- **Ghi nhận giờ làm (LogWork):** Hoàn thiện API ghi nhận số giờ làm việc hằng ngày (sử dụng kiểu DECIMAL chống sai số).
- **Quy trình Duyệt:** Triển khai các API xử lý nghiệp vụ cho Manager: `Approve` (Duyệt) và `Reject` (Từ chối).
- **Quy trình Hậu kiểm:** Triển khai API `Correct` (Sửa chữa) và `Void` (Vô hiệu hóa) khi bản ghi bị sai sót, đảm bảo tính bất biến của lịch sử (không dùng lệnh xóa vật lý DELETE). Khắc phục thành công sự cố sai lệch tên cột (`reviewed_note` -> `review_note`).
- **Khóa sổ (Time Lock):** Hoàn thiện tính năng khóa kỳ báo cáo theo Tháng/Năm, ngăn chặn sửa đổi dữ liệu sau khi chốt lương/báo cáo.

## 6. Module Báo cáo và Trích xuất (Reports)
- Xây dựng hệ thống API truy vấn và tổng hợp dữ liệu tốc độ cao cho **Manager Dashboard**.
- Xây dựng báo cáo **Task Summary** (Tổng hợp tiến độ Task).
- Xây dựng báo cáo **Timesheet Detail** (Chi tiết giờ làm).
- **Tính năng Xuất PDF:** Khảo sát rủi ro thư viện WeasyPrint trên môi trường Windows và ra quyết định chuyển đổi kiến trúc sang dùng `xhtml2pdf`. Chuyển đổi dữ liệu thành các Template HTML chuẩn chuyên nghiệp và xuất thành file PDF thành công.

## 7. Các Module Dịch vụ Cốt lõi (System Services)
- **Lưu vết Hệ thống (Audit Log):** Thiết lập cơ chế ghi dấu vết tự động. Mọi thao tác nhạy cảm (như chốt sổ giờ làm, sửa đổi giờ, xuất báo cáo) đều được hệ thống lẳng lặng lưu lại lịch sử `old_values` và `new_values` để phục vụ công tác thanh tra.
- **Hệ thống Thông báo (Notification Manager):** Xây dựng nền tảng Notification đa kênh (`SYSTEM`, `EMAIL`). Đã cấu hình luồng dữ liệu thông báo và đặt sẵn các "chốt chờ" (placeholders) cho Celery (để gửi Email bất đồng bộ) và Django Channels (để đẩy thông báo Real-time qua WebSocket) sau này.
