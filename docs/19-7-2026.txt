Tổng kết trạng thái WorkTracker Manager Backend
Tính đến hiện tại, các phần chính của backend nhóm Manager đã được triển khai theo từng giai đoạn như sau.

Đã hoàn thành các file nền tảng dùng chung cho Manager:
system/permissions_manager.py
system/scoping_manager.py
system/services/audit_manager_service.py
system/services/notification_manager_service.py
Đã thống nhất

IsManagerRole
HasPermissionCode
Không dùng tên cũ:

- Ghi AuditLog

- Best-effort realtime/email placeholder
- Kiểm tra active user
- Kiểm tra role Manager

7. Trạng thái hiện tại
Có thể xem trạng thái hiện tại là:
Manager backend implementation cơ bản đã hoàn thành theo module:
system → projects → tasks → timesheets → reports
Các bước kiểm tra đã OK:
- python manage.py check
- Import checks
- Reverse route checks
- Task module test OK
- Reports route reverse OK
- openpyxl import OK
Các bước cần làm tiếp theo
Từ thời điểm này, không nên viết thêm module mới ngay. Nên chuyển sang kiểm thử, rà soát bảo mật, permission và tài liệu API.
Bước 1 — Test chức năng Reports bằng dữ liệu thật
Cần test các endpoint:
GET  /api/manager/dashboard/
GET  /api/manager/reports/task-summary/
GET  /api/manager/reports/timesheet-detail/
POST /api/manager/reports/export/
Cần kiểm tra:
- Dữ liệu chỉ nằm trong scope Manager
- Filter hoạt động đúng
- Summary tính đúng
- Export XLSX tải được file
- AuditLog có REPORT_EXPORTED
Bước 2 — Test end-to-end toàn bộ Manager flow
Cần test theo luồng thật:
1. Manager tạo Job
2. Manager tạo Task trong Job
3. Assign Employee
4. Employee có LogWork hoặc tạo LogWork test
5. Manager approve/reject/correct/void LogWork
6. Manager lock/unlock kỳ công
7. Dashboard và Reports phản ánh đúng dữ liệu
8. Export báo cáo
Mục tiêu là kiểm tra toàn bộ dữ liệu liên kết giữa:
Job → Task → LogWork → TimeLock → Report
Bước 3 — Test bảo mật scope giữa nhiều Manager
Cần tạo thêm một Manager thứ hai.
Mục tiêu:
Manager A không được thấy dữ liệu của Manager B
Cần test:
- Job khác Manager
- Task khác Manager
- LogWork khác Manager
- TimeLock khác Manager
- Reports với job_id thuộc Manager khác
Kết quả đúng phải là:
403 hoặc 404
Không được trả dữ liệu.

Bước 6 — Chuẩn hóa permission code
Hiện tại các view chủ yếu dùng:
IsActiveAuthenticated
IsManagerRole
Chưa bật chặt:
HasPermissionCode
Cần làm sau khi test nghiệp vụ ổn.
Công việc:
1. Chốt danh sách permission code
2. Seed vào bảng permissions
3. Gán permission cho role MANAGER
4. Thêm required_permission vào view/action
5. Bật HasPermissionCode
6. Test user thiếu quyền bị chặn đúng
Ví dụ permission nhóm Manager:
job:view
job:create
job:update
job:change_status
task:view
task:create
task:update
task:assign
task:review
task:cancel
task:comment
task:attachment

timesheet:unlock
report:view
report:export
Danh sách này cần đối chiếu tài liệu trước khi chốt.
